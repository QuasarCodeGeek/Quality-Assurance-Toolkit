## Overview

Non-Functional Testing is a type of software testing that evaluates the quality characteristics of an application beyond its functional behavior.

While Functional Testing verifies **what the software does**, Non-Functional Testing evaluates **how well the software performs** under various conditions.

Non-Functional Testing helps ensure that an application is reliable, secure, efficient, compatible, and capable of delivering a positive user experience.

## Objective

The objective of Non-Functional Testing is to evaluate whether the software meets the required quality standards for performance, security, reliability, usability, compatibility, accessibility, and other operational characteristics.

---

## Common Non-Functional Testing Types

The following testing types are commonly performed during Non-Functional Testing:

| Testing Type          | Primary Purpose                                                                         |
| --------------------- | --------------------------------------------------------------------------------------- |
| Performance Testing   | Evaluates system responsiveness and stability under expected workloads.                 |
| Load Testing          | Verifies system behavior under expected user or transaction loads.                      |
| Stress Testing        | Determines how the system behaves beyond normal operating capacity.                     |
| Security Testing      | Identifies vulnerabilities and verifies security controls.                              |
| Compatibility Testing | Verifies operation across supported devices, browsers, operating systems, or platforms. |
| Accessibility Testing | Confirms that the application can be used by people with disabilities.                  |
| Usability Testing     | Evaluates how easy the application is to learn and use.                                 |

---

## Benefits

* Improves overall software quality.
* Increases application reliability.
* Enhances security and data protection.
* Delivers a better user experience.
* Reduces operational risks after deployment.

---

## Best Practices

#### Planning

* Define measurable quality objectives.
* Identify applicable non-functional requirements.
* Select appropriate testing tools and environments.

#### Execution

* Test using realistic workloads and environments.
* Monitor system behavior throughout testing.
* Document findings and performance metrics.

---

## In Practice

A development team completes the functional testing of an online learning platform.

Before deployment, the QA team performs Non-Functional Testing by measuring application performance under expected user traffic, verifying compatibility across supported browsers and devices, assessing security controls, evaluating accessibility, and ensuring that the user interface remains intuitive for its intended audience.

These activities help confirm that the application is ready for production beyond simply meeting its functional requirements.

---

## Developer Tips

* Consider non-functional requirements during system design.
* Optimize application performance early.
* Follow secure coding practices.
* Design interfaces with accessibility and usability in mind.
* Test applications using realistic environments whenever possible.

---

## Common Mistakes

* Focusing only on functional requirements.
* Delaying Non-Functional Testing until late in the project.
* Ignoring performance and security requirements.
* Testing only under ideal conditions.
* Assuming an application is production-ready because all functional tests passed.

---

## Summary

Non-Functional Testing evaluates the quality characteristics of a software application, including its performance, security, compatibility, accessibility, usability, and reliability.

By validating these attributes, development teams can deliver software that not only functions correctly but also performs effectively in real-world environments.
