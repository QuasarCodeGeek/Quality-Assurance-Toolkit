# Module 04 — Functional Testing Types

## Overview

This module focuses on the most commonly used Functional Testing types performed throughout the software development lifecycle.

Functional Testing verifies that software behaves according to its functional requirements and business rules. Depending on the project's phase and objectives, different testing types are used to validate individual components, integrated systems, or complete business workflows.

The guides in this module introduce the functional testing approaches most frequently used in real-world software projects.

---

## Learning Objectives

After completing this module, you should be able to:

* Understand the purpose of each functional testing type.
* Identify when Smoke, Sanity, Regression, and User Acceptance Testing should be performed.
* Distinguish between Integration Testing, System Testing, and End-to-End (E2E) Testing.
* Select the appropriate testing approach for different stages of the development lifecycle.

---

## Guides

| Guide                             | Description                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------------- |
| **Smoke Testing**                 | Verifies that the application's core functionality works before detailed testing begins. |
| **Sanity Testing**                | Confirms that specific changes or bug fixes work as expected.                            |
| **Regression Testing**            | Ensures existing functionality continues to work after software changes.                 |
| **Integration Testing**           | Verifies interactions between integrated modules or services.                            |
| **System Testing**                | Validates the complete integrated application against its requirements.                  |
| **End-to-End (E2E) Testing**      | Tests complete user workflows across the entire system.                                  |
| **User Acceptance Testing (UAT)** | Confirms that the software meets business needs and is ready for production use.         |
